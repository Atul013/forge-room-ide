# Network Room readiness, assistance and impacts

The Readiness tab combines owner-published remaining estimates, blockers, linked file names and **manual** check/preview/submission declarations. Profiles use optimistic revisions: a stale update is rejected instead of overwriting newer data. Only the current task owner can publish readiness or request assistance. Host status is not permission to impersonate an owner.

Risk explanations compare the host-authoritative task due time and running Room countdown with the longest unfinished dependency path. Estimates assume independent branches can proceed in parallel; this is not a resource schedule or guarantee. Missing current-owner estimates, cycles and missing dependencies remain unknown. A paused/ended countdown does not consume the task's wall-clock deadline budget. Manual success or NotRequired is never independently verified test/build/submission evidence.

Assistance recommendations require current-owner opt-in. The owner explicitly opens a help request, closes/reclaims it, or opts out; opting out closes the current request. No agent is started, no task is completed, and no ownership changes automatically. Handoff remains the existing explicit request/accept flow. A new owner must review prior-owner metadata; prior assistance opt-in is not inherited.

Impact notices identify source and target task, a source-linked relative path, a full 40/64-character owner-declared commit/digest reference and an explanation. Only the source owner can declare them. The target must depend on the source or publish the same linked file. Only the current target owner can acknowledge or dispute. Acknowledgements by former owners require current-owner review; disputes remain visible risks. These are human observations, not verified authorship or semantic analysis.

**Local Git impact suggestions** are an explicit, cancellable background scan. It checks up to 16 existing, safe, current-owner linked files and returns up to 64 relationship hints from saved tracked staged/working diffs. Suggested targets come from declared dependencies or matching published file links. The supplied Git HEAD is the base commit reference, not a digest of the uncommitted change. Inspect the actual diff and confirm semantic impact before separately publishing an impact notice. No diff body, untracked content, deleted file content or code is transmitted by scanning. Missing, sensitive, linked and oversized source files are skipped with local warnings. Work is checked for cancellation/time window between bounded Git calls; cancellation may wait for the current Git call. Late results and cached suggestions are discarded after root, identity or trust changes. Absence of a suggestion does not prove absence of impact.

**AI task brief:** Stage an individual task's coordination data into the AI context picker. It starts excluded and requires inspection, Include and the normal request controls before provider transfer. The whitelist includes that task, its readiness/help records and up to 16 related impact notices; it excludes DMs, messages, patches and local files. It grants no AI file or command capability.

All network readiness data is explicit Room-shared metadata in the current host's ephemeral authority. It is not imported from saved local Rooms and disappears when hosting ends. Limits are 100 profiles, 100 per-task help records, 128 impact records and eight linked paths per profile. Paths receive the existing sensitive-path filter but are declarations, not proof the host possesses those files. Keep secrets out of shared notes.

This is an additive protocol extension. Hosts advertise readiness support in SharedSnapshot; an older snapshot defaults to unsupported and the new UI explains that state. Legacy task/message/patch behavior remains unchanged. Existing TLS identity, operation deduplication, reconnect and authorization still apply.

Source/protocol/process tests do not prove visible desktop operation or a physical two-machine trial. Readiness is recommendation and coordination, not autonomous deadline rescue or gated agent scheduling.
