# Native Room Launch Center

Open Room Launch Center from the Network Room controls. Start with Blank Room, Feature delivery, Bug investigation or Hackathon; edit structured task keys, titles, criteria, dependencies, priority, relative deadlines, milestones, countdown and release requirements, or inspect the strict JSON manifest. Save a new immutable local version, import/export a new portable JSON file, or explicitly capture public setup from the hosted Room.

Blueprints are bounded version-1 declarative intent (256 KiB, 100 tasks, 20 milestones, 24 release checks, seven-day countdown). Validation reuses the authoritative task-plan graph checks. Unknown fields, duplicate or missing keys, invalid cycles/references and unsupported limits are rejected before hosting. Capture excludes member identities, Room identity, invites, chat/DMs, evidence, patches, readiness declarations, completion and release-check results. Deadlines become bounded whole hours relative to launch; overdue deadlines become zero hours. Every new task/check belongs to the launching member, with completion reset. Existing work requires an explicit subsequent owner handoff.

Review freezes the full blueprint, content digest, display name, bind address and countdown choice. Confirm creates a fresh TLS host and joins the launcher on a worker, configures the full setup before returning it, and adopts its prepared connection without joining twice. A failure closes the temporary host; no external invite is published automatically. Closing/cancelling a pending launch prevents adoption. A delayed result cannot replace an existing host or connection. The review is setup integrity, not signed publisher authenticity.

The countdown is paused by default. Launch shares only the network Room's normal public data; it does not open a project, share files/terminals, start an agent, make provider calls or enable journaling. Explicit Network Room controls remain available for managed/external journaling, invites, handoffs and recovery. The legacy direct blank-host path remains available.

Saved versions use checksummed create-only synced FRC1 records under `%LOCALAPPDATA%/Forge Room Early Preview/room-blueprints`; 128 versions and a bounded 256-entry directory scan are supported. Invalid versions are reported and preserved. No overwrite, automatic retention deletion or credentials are stored. Library/import/export work runs off the UI thread. Imported and pack-staged blueprints remain drafts until saved/reviewed; built-in starters are not claims of completed work. Unfinished editor drafts remain in memory only.

Packs now support a ninth `room_blueprint` resource kind. Workshop can author it; strict core parsing validates it; selective activation makes it inspectable. The explicit Stage action opens the Launch Center without hosting. Activation/install never launches a Room or grants execution authority. Older binaries do not support this new resource kind; packs with only the original kinds remain compatible.

Tests cover strict graph/schema/size rules, complete fresh setup, launcher ownership, dependency remapping and identity/message exclusion on capture/relaunch; saved immutable versions, corrupt-file preservation, bounded export/import; native editor/review frames at regular/narrow sizes and connection adoption/refusal. Exact local/Windows/package receipts belong in progress.md. These tests do not prove visible desktop, real native-provider inference or physical two-client reachability. Those acceptance gates remain open under the recorded environment limits.
