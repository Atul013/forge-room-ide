# Native Release Evidence Desk

Open Release Evidence Desk from a Project tools page. The modeless window remains available while the editor/Room panel changes. A dossier combines a source anchor, artifact fingerprints, release notes and five independent attributed reports: Source/CI, Package/install preservation, Visible desktop/interaction, Real native provider and Physical two-client. Every gate begins Unknown. ReportedPass/ReportedFail requires an observer, note and timestamp; references are text only, never fetched or executed. The Desk does not detect CI completion or independently verify human acceptance reports.

Bind and capture the trusted active Git project to record commit, tree, a status digest, dirty/untracked count and observation time. Capture checks HEAD/status twice for stability, uses the existing bounded read-only Git adapter with fsmonitor disabled, and does not record path listings in portable source metadata. Dirty/untracked source may be recorded but cannot pass a checked handoff. Ignored files are outside this Git source identity. Changing the anchor resets all five reports; capturing identical source preserves them.

Attach explicitly chosen regular non-linked files for bounded streaming SHA-256 fingerprints (64 receipts, 512 MiB each, 2 GiB total). Private file bindings are displayed locally. Hashing does not inspect ZIP entries, verify license completeness, install an executable, validate signatures or run a launch probe. Replacing the same artifact name with changed bytes, adding or removing a receipt resets reported acceptance; identical bytes preserve reports. Invalid additions preserve the previous dossier atomically.

Recheck compares the frozen clean source and every bound artifact's bytes, then checks source again after hashing. A changed/missing file or source fails closed. Files are checked sequentially; there is no atomic filesystem snapshot/lock over the entire artifact set. A successful check is a time-bounded integrity observation. It cannot turn an Unknown/manual desktop, provider or physical-client result into independently verified acceptance.

Save new private versions under `%LOCALAPPDATA%/Forge Room Early Preview/release-evidence` as synced create-only checksummed FRC1 records (1 MiB, 128 versions, 256-entry scan limit). Invalid saved versions remain listed/preserved; there is no automatic deletion or reset. Private versions retain local source/file paths. Unfinished edits remain in memory until explicitly saved; invalid required report fields must be corrected before save/export. Loading a prior version preserves its original reports as claims and requires local rechecking before checked export.

Portable JSON exports contain the typed dossier, digest and an optional local source/file recheck time; local binding fields are omitted. User-authored notes, observer names and references are exported intentionally and can themselves contain sensitive text, so review them. Frozen export review shows exact source/file bindings and artifact hashes before choosing a new destination. Both draft and checked export refuse replacement. Checked export rechecks source/files immediately before creating the report; it can accurately export outstanding/failed acceptance gates and never publishes a release. Draft export does not recheck local bytes.

Import validates strict fields, bounds and the dossier digest, then stages the dossier with no local source/file bindings. Imported timestamps/fingerprints/reports are untrusted metadata, not current local verification or publisher authenticity. Bind source and attach matching files explicitly before a checked export. Comparison shows differing identities, source, manual gate reports and added/absent/changed artifact bytes. Capture-clock-only source differences are ignored; no dossiers are automatically merged.

Explicit Room staging sends only title, source commit, five labelled manual outcomes and artifact count into the existing matching task's evidence draft. Observer names, notes, references, paths, file names and hashes are omitted. The native Room editor still requires explicit attach/publication; no task completes and no Ship check is automatically reported. Room identity/task validation remains authoritative.

The Desk never invokes providers, deploys, publishes, runs artifacts or claims desktop/physical reachability. Parsing/import/library/source/hash/export work runs on workers; rendering uses cached records. Local and exact-head Windows/package evidence belongs in progress.md. Native frame tests are separate from visible desktop acceptance, and same-host process tests remain separate from a physical two-client trial.
