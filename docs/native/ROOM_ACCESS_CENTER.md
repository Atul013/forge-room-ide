# Native Room Access Center

Open Room Access Center from the Team/Chat Network Room controls. The modeless native center combines Join review, Connection bookmarks and Host invitations. It remains available when the Room dock is hidden. Existing local Room data stays private; this feature introduces no discovery service, cloud account, provider calls or transport version change.

## Reviewed joining

Paste a private invite into the masked in-memory editor. Review freezes its exact typed invite, display name and optional local project association. Inspect Room name, specific host address, loopback-versus-network scope and full TLS certificate SHA-256. The certificate comes from the invite; confirm it privately with the sender. It is not account/publisher authentication. Host expiry/revocation/single-use validity cannot be proved by inspecting the text and is enforced by the server.

Selecting a bookmark compares its stored name/address/certificate before connection; changed identity requires explicit acknowledgement. An unavailable selected bookmark cannot silently downgrade to an unbound review. No bookmark, import or selection initiates a connection or opens a project. The native TLS join runs on a worker. After joining, changed public Room ID, unexpected member name or existing task ownership requires a second review before local adoption. This is especially relevant to owner-reclaim invites. Only the prepared client is adopted; no second join consumes another invite. A delayed result cannot replace an existing connection or hosted Room.

Cancel/close prevents pending adoption. A completed temporary connection sends leave on a worker; the invite may already be consumed and host activity may include join/leave. Closing the center clears private invite input and the last host-issued private copy. Rust memory is not claimed to be cryptographically erased. Native Access can leave a member connection while preserving a local host. Rejoining a retained owner requires a fresh private owner-specific reclaim, not a fresh guest identity.

## Durable connection bookmarks

Only an adopted successful connection registers a local observation. Each entry stores Room name/public Room ID if supplied, specific address, certificate fingerprint, optional private project association, label/pin and latest observed local join time. These are cached metadata, never online/reachability proof. Older protocol-three peers without a public Room ID remain joinable, with that identity explicitly marked not supplied. Hex fingerprints are normalized on import.

Private catalog location is `%LOCALAPPDATA%/Forge Room Early Preview/room-connections`. Version-1 strict FRC1 checksum records use synced create-only writes, a short exclusive writer lock, exact catalog seals for edits, a 512 KiB record bound and 64 entries. Eight catalog versions are retained; only old known regular catalog files are pruned after the new synced version exists. Directory scans stop at 256 entries. Incomplete tails can fall back to the last complete record; complete corruption closes metadata writes while preserving files. Direct private-invite joining remains available. Removing a bookmark changes the current catalog only; retained versions can still contain public metadata. It never removes projects, Room history, recovery files or host grants.

Registration is separate from network success. A failed/busy metadata writer does not disconnect the adopted client. The latest adopted public connection metadata remains in memory with its original observation time and can be explicitly saved/retried without reconnecting. Repeat saves do not invent join counters or new join times; newer saved observations are not regressed by an older retry. This in-memory retry is not a durable queue and disappears on app exit.

Public bookmark export/import contains name/label, Room ID when available, address and certificate hash only. Project paths, locally observed times, full certificates, authentication tokens, session credentials and messages are excluded. Imports are bounded to 128 KiB/64 profiles, strictly validated, inspected by digest and confirmed against the frozen catalog seal. They add new entries only; existing labels/pins/local history are preserved. Imported entries have no locally verified join observation. Export creates a new file and refuses replacement. No imported text is executed or sent to a host.

## Host invitation lifecycle

A live host can inspect every currently retained grant, including the initial launcher and owner-reclaim grants: non-credential public ID, unused/used/expired/revoked status, monotonic remaining lifetime, reclaim target and retained session identities. Expiry denies a new join but does not end an already joined session; explicit revocation does. Fresh guest invites and owner-specific reclaim invites can be created for 1-3600 seconds, copied explicitly and sent privately. Discarding the local copy does not revoke a grant. Host grant secrets are volatile and never included in metadata/profile exports or checkpoints.

Review one or more selected grants before revocation. The immutable review freezes host/Room scope, selected grant state and affected identities; new joins, changed scopes or missing grants reject the whole action before mutation. Natural countdown/leased-presence changes do not invalidate a review. Confirm uses one host-local policy mutation and journal flush before successful acknowledgement. Revocation may disconnect the hosting user's member session; the host authority remains separate. The UI can detach the local member without ending the host.

Reclaimed identities and departed task-owning members return to the offline retained-owner list on leave, expiry or either revocation API. Task ownership/status/criteria are unchanged, all old authentication is lost, and guests without tasks are not retained merely for leaving. Task focus and shared code location are cleared on session retirement; reclaim never resumes sharing automatically. Only the host can issue a fresh identity-specific invite, and it must go privately to the original owner. This is capability recovery, not a verified account system or permission to replace an owner.

## Evidence and limits

Core and independent-peer tests cover secret-free summaries, stale all-or-nothing revocation, unaffected clients, fresh-process reclaim, task-owner/recovered identity retention and privacy-preserving presence retirement. Native tests cover successful adoption/race refusal, cancellation, changed identity review, metadata locking/staleness/torn/corrupt states, retry without reconnection, import privacy/legacy identity and regular/narrow offscreen pages/reviews. Exact local/Windows/package/downloaded-build receipts belong in progress.md. Same-host processes and offscreen frames do not establish physical two-client or visible desktop acceptance. The native desktop pipe remains unavailable; native real-provider and physical-device gates stay independent and open.
