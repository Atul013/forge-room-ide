# AI context and project Skills

The AI panel can capture local snapshots of editor selections, the active file's staged and working Git diff, displayed Problems, the active terminal tail, in-workspace debugger stack frames and local Room tasks. Capture does not send data. Inspect a snapshot and select **Include** to attach it to the next prompt. Native HTTP requests still show the complete outgoing request before Send. CLI requests include the selected snapshots under the chosen CLI permission mode.

Snapshots are historical, timestamped and bounded: at most eight items, 32 KiB per item and 128 KiB total retained text. Oversized text is marked truncated; terminal capture preserves the tail. Recapture does not refresh an included snapshot silently: the replacement starts excluded. Clear, remove or uncheck to stop including it in future requests. Changing selected context starts a fresh provider conversation and clears retained native history. Previously transmitted data may remain with the provider; this does not remotely delete it.

All snapshots belong to one open workspace. Switching workspace, removing trust or starting a new chat clears them. Credential/repository-internal paths and linked files are rejected through the existing source-path checks. Terminal capture requires a terminal initially created in this workspace; its current shell directory and the provenance of printed text cannot be inferred. Review terminal text for secrets. Problems may be stale; capture does not run a new check. Debugger capture excludes variable values and evaluation. Room capture includes local tasks only, excluding messages, DMs and the separate network Room. Git capture uses the existing literal-path, no-external-diff/no-textconv reader and excludes untracked-file contents.

Controlled build accepts explicitly included context when its session starts, alongside its selected path grants. This text does not grant file writes or checks. Context choices remain locked until the session ends. Continuations retain the sealed initial context without attaching it repeatedly. Late background captures are discarded after trust, root or controlled-session state changes.

**Project Skills:** explicit discovery scans `SKILL.md` and one child directory under `.agents/skills`, `.codex/skills`, `.claude/skills` and `skills`, bounded to 64 entries. Each entry shows its path, name and simple frontmatter description. Inspect the full Skill as a snapshot, review its license, scripts and network requirements, then select Include. Only that text is attached. Referenced scripts/assets are never automatically loaded or run. A Skill is procedural guidance; it cannot override native permissions, approvals or budgets. Direct CLI agents retain their independently selected CLI capabilities.

This project discovery path is local request context. The Studio Packs window also provides a separate local Skills library for importing one exact `SKILL.md` file into the immutable resource-pack store, reviewing a specific version, and selectively enabling it. The importer supports a bounded subset of frontmatter, not every `SKILL.md` dialect. Neither path is a remote catalog, execution sandbox, or scheduler. A library Skill must be active before it can be captured; its AI Context snapshot still starts excluded. Existing chat storage can retain model responses which quote supplied context. See [ROOM_SKILLS_LIBRARY.md](ROOM_SKILLS_LIBRARY.md) for import limits, provenance and acceptance boundaries.
